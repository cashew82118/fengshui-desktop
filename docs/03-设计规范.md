# 03 设计规范 · 桌面风水分析器

> 版本 v1.0 ｜ 2026-10-24
> 目的：让界面看起来像一本旧书上的图，而不是一个监控工具。

---

## 1. 气质定位

**宣纸、朱墨、细线**。底色暖白，文字近墨，五行用低饱和色。禁止：
- 渐变、投影、发光、玻璃拟态
- 圆角大于 8px 的卡片
- 任何"科技感"的深色面板或霓虹色
- emoji（卦象一律用汉字）

## 3. 字体

**2026-10-27 定稿：正文字体可切换，默认黑体；宋体位置永远宋体。**

| 位置 | 字体 | 说明 |
|---|---|---|
| 品牌标题「桌面风水」 | 宋体 `SimSun` 17 | **固定**，不随设置变 |
| 九宫卦名 | 宋体 14 | **固定** |
| 总评正文 | 正文字族 12 | 跟设置走（2026-10-27 起） |
| 印章「風」 | 宋体 12 | **固定** |
| 总分数字 / 序号 | `Georgia` 40 / 11 | **固定** |
| 评级（平·可用待理） | 正文字族 13 | 跟设置走 |
| 分条小标题 | 正文字族 11 | 跟设置走 |
| 正文 | 正文字族 10 | 跟设置走 |
| 说明／注释／单位 | 正文字族 9 | 跟设置走 |

**正文字族**在「设置 → 字体」里选，存 `prefs.json` 的 `font_family`，默认 `Microsoft YaHei`（黑体）。
共 13 个选项：黑体、宋体、新宋体、华文中宋、华文宋体、仿宋、华文仿宋、楷体、华文楷体、隶书、华文隶书、华文行楷、华文新魏。
设置面板里每个选项后面跟一句实测标注（小字清楚／略虚／虚／糊），选之前就知道代价。

- 固定宋体只剩三处：品牌标题、九宫卦名、印章「風」。总评正文原本也固定，
  2026-10-27 用户要求改成跟随设置（它属于「正文字」而不是「标题字」）。
- 字体改动只影响 7 个角色：grade / body / small / tiny / card / cap / tip。
- 不用 Inter / Roboto / Arial（AI 味的默认脸）。离线约束下只用系统字体，**不引外链字体**。
- 字号不得小于 9（选「小」档时被倍率压到 8，是唯一例外）。

### 3.0.1 字体相关实测结论（2026-10-26~27，别再踩）

1. **Windows 只给少数几款做了 9pt 内嵌点阵**。实测在 9pt：宋体、新宋体锐利；
   仿宋、楷体细到发虚；华文系列、隶书、行楷、新魏会糊成一团。所以「小字清楚」和
   「有古风味道」在同一款字体上很难兼得——这是系统限制，不是审美问题。
2. **13pt 以上不受限制**。大字号抗锯齿撑得住，隶书、行楷都能用。
3. **宋体/楷体/仿宋都没有可用的真粗体**。Tk 的 `bold` 是"描粗"合成，会把笔画糊掉，
   看起来反而像黑体。所以小标题不加粗，层级靠字号（13/11/10/9）+ 颜色（ink/sub/weak）。
4. **衬线体的 linespace 比雅黑小 5px**（同为 9pt：宋/楷/仿 12，雅黑 17）。
   换到衬线体后整个界面会变紧：单行控件用 `pady` 补，多行 Label 内部行距改不了，
   只能靠加深字色、拆成多条 Label 缓解。
5. **探测字体必须用 `Font(...).actual("family")`**，不能用 `families()` 判断：
   本机 families 只返回中文名（「宋体」「楷体」），但直接写 `"SimSun"` / `"KaiTi"`
   也能解析到；而写错的族名不会报错，只会静默回落成「宋体」——
   正好可以拿这一点当判据（回落成宋体 = 没有这个字体）。
   实现在 `main._resolve_body()`，失败一律退 `theme.BODY_FALLBACK`。

### 3.1 字号档位（2026-10-24 新增）

界面上「字号 A−／A＋」四档，整体倍率作用在**所有**字体上（含盘面卦名、说明、图例）。

| 档位 | 倍率 | 正文（仿宋 10） | 说明（仿宋 9） | 总分数字 |
|---|---|---|---|---|
| 小 | 0.90 | 9 | 8 | 36 |
| 标准（默认） | 1.00 | 10 | 9 | 40 |
| 大 | 1.13 | 11 | 10 | 45 |
| 特大 | 1.27 | 13 | 11 | 51 |

- 换字号会重建界面（而非重设每个控件），代价是几十毫秒，换来不会漏改。
- 盘面上下留白随字号联动，字号调大时盘自动让位，不会把图例顶出画布。
- 字号与主题一起存在 `data/prefs.json`，下次启动沿用。

### 4.1 五档视图与功能说明（2026-10-25 扩为五档）

顶栏放一个**分段控件**（现状 ／ 最小调整 ／ 全部重排 ／ 优先文昌 ／ 优先财库），
选中项白底＋朱色＋粗体，未选中落在底槽里。

**每个档位上方必须有一句功能说明**（左栏、盘的上方，随档位切换）：

| 档位 | 说明文案要点 |
|---|---|
| 现状 | 「你桌面的真实样子……只读，不改动任何东西。满分 100，当前 N 分。」 |
| 最小调整 | 「只挪明堂溢出与中宫里的图标，其余一动不动……移 N 个 → M 分（+K）。」标注**可照着做** |
| 全部重排 | 「按外实内虚重新摆一遍……真要这样得手动挪几十次。」标注**只看效果** |
| 优先文昌 | 「把文书、笔记、学习类集中到本命文昌位 X 宫（方向）……移 N 个 → M 分（±K）；比最小调整动得多，这是代价。」未填生辰时落**巽宫**并说明「巽为文昌总位，填了生辰会换成本命的」 |
| 优先财库 | 「把工具、管理、生产力类集中到生气位 X 宫（生气主财源）……」。未填生辰时落**乾宫**（乾为财库） |

功能说明不是 tooltip——它常驻在盘上方，切换档位就换。用户不该为了知道按钮干什么而去悬停。

**移动清单**（2026-10-25 加）：非「现状」档且确有移动时，说明行右侧出现
「移动清单 · N」（弱文字色、无边框、悬停转主色）。点击开非模态 Toplevel：
Treeview 四列「图标｜从｜到｜缘由」，宫位写成「坎宫 北」，中宫单列；
底部「共 N 个 · 本清单只是建议」。Esc / 标题栏 X /「关闭」均可收；
换主题或重新分析时随重建关闭（内容已过期）。

**推演的两条硬约束**（`project.focus`）：① 中宫恒空；② 目标宫有容量上限——
明堂（正前方那格）最多 4 个，其余宫 8 个；文昌位恰落明堂时会少放，文案里说明。

## 5. 九宫盘绘制

| 项 | 规范 |
|---|---|
| 画布 | 按盘真实宽高比等比缩放，**随窗口自由缩放、不设上限**（只受可用宽高约束），居中 |
| 外框 | 1px 主题色 `line_outer` |
| 宫内线 | 1px 主题色 `line`（Canvas 最小 1px，无法做 0.5px） |
| 宫内底色 | 主题色 `cell_tint`，混合比例按图标数：0→0、1–4→0.10、5–9→0.18、10+→0.26 |
| 中宫特例 | 中宫为空时填主题色 `center_empty`，正中写"中宫空 · 吉" |
| 图标方块 | **圆角方形**，圆角半径 = 边长 × `0.26`，边长 = `cell_w * scale * 0.5`，**最小 3px**；**按五行着色**（见 2.2），无五行时填墨色 |
| 宫名标签 | 每格左下角，主题色 `accent`；空宫用弱文字色写"空" |
| 方位提示 | 盘上方一行"▲ 视线尽头 · 明堂"，下方一行"▼ 你坐的位置 · 坐方" |
| 四象提示 | 盘下"左青龙 宜动　·　右白虎 宜静" |
| 五行图例 | 盘下最后一行，五个圆点 + 字，间距随字号走，居中 |
| 悬停图标 | 放大到 **1.55 倍**并加一圈主色细边；浮出提示：名称 / 五行 / 宫位 |
| 悬停宫格 | 该宫描一圈主色细线（1px，压在图标之下，不挡名称） |
| 点击图标 | 一圈圆角方框自内向外扩散并淡去（涟漪，460ms） |

**宫底染色只能走 `render.cell_fill()`**：`_mix(color, bg, w)` 里 `w` 是 **color 的权重**，
第一个参数是"终值"。写成 `_mix(bg, color, w)` 就变成"越进场越接近底色"——表现为
**加载时闪一片色块、随后整盘发白**（2026-10-24 踩过，四套主题全中）。这个函数还负责入场进度：
`progress=0` 只显 32%，`1` 才是完整染色。

**圆角怎么画**：Canvas 没有圆角矩形，用 `render.rr_points()` 采样四角圆弧（每角 5 点，共 20 点）生成多边形。
点数固定，所以放大缩小时可以直接 `coords(item, *rr_points(...))` 换点，不必重建图元。

**禁止**在盘上画热力模糊、光晕、雷达圈。

## 6. 诊断卡

单条诊断的固定结构（四行，缺一不可）：

```
┌────────────────────────────────────────────┐
│ [忌] 中宫受压                        −6    │  ← 14px 粗 + 右对齐扣分
│ 中宫内有 2 个图标，最近者距中心 0.12R       │  ← 12px 次文字：数据依据
│ 理：中宫为气之枢纽，宜虚不宜实，实则事滞     │  ← 12px 主文字：风水原理
│ 改：把「时稿集」移至艮宫                    │  ← 12px 主色：可执行建议
└────────────────────────────────────────────┘
```

- 卡片**不用四边框**。改为「左侧 2px 竖线（按吉凶着色）＋ 底部 1px 发丝线」的**眉批样式**，
  像书页边上的批注，而不是一张张卡片（"万物皆卡片"是 AI 味的源头之一）。
- 内边距：上下 11/9，左（竖线后）11，右 12。
- 判定标签用**文字**（忌／平／吉／述），颜色只是辅助——不靠颜色单独传达含义。
- 扣分为 0 的"吉"条目也列出（给正反馈），但排在有扣分的条目之后。

### 6.1 页签

右栏诊断区顶部三个页签：**「分条」「总评」「历史」**，默认停在「分条」。

- 选中态：主色 + 粗体；未选中：弱文字色常规。底部有一条 2px 指示条滑过去。
- 切换只换内容，不重算（重算只发生在扫描与换朝向时）。

**历史页**（2026-10-24 新增）

| 区 | 内容 |
|---|---|
| 摘要 | `共 N 次记录（最多保留 200 条） 最高 X ／ 最低 Y ／ 最近 MM-DD HH:MM · 只存数字，不存文件名` |
| 趋势图 | 折线 + 数据点，最多取最近 40 条；纵轴**按本次数据自适应**（跨度 <12 时向两端扩到 ±6），否则 60–80 的变化会被压成直线；两端标注刻度值；切进来时逐段展开（620ms） |
| 快照区（2026-10-25 加，10-26 改） | 一行 `桌面快照 ［保存本次分析］ 共 N 张 · 只在本机`；月份导航 `‹ 2026 年 10 月 · N 天有记录 ›`；7 列日历（**所有日期可点**；有快照的日子 `sunk` 米底 + `accent` 加粗数字 + `seal` 红点，选中日 2px `accent` 描边，今天 1px `line_outer` 描边）；当日列表先给日期头 `M 月 D 日（今天）… N 张`，最多 3 行 `HH:MM ｜ N 分 ｜ 评级 ｜ 查看 ›`，超过 3 张给「另有 N 张 · 点开看全部 ›」打开当日清单 |
| 明细 | 最新在上，最多 40 条：`时间 ｜ 分数 ｜ 断语 ｜ N 个 · M 宫 ｜ 与上一条的增减`。增用吉色、减用忌色、持平用弱文字色 |

- 历史页与 `.jsonl` 一一对应，**没有任何写入口**，也不删除记录；快照是**唯一写入口**，
  由用户点「保存本次分析」触发，写 `data/snapshots/`。
- 每次扫描会把新记录立刻反映到列表（不必重开）。
- **顺序**：摘要 → 趋势图（常驻，不随快照区滚动）→ 快照区 → 分隔线 → 全部分析记录。
- 快照查看弹窗：盘面（按快照保存的朝向重画）+ 六项一行 + 前 3 条诊断；非模态，Esc/X/关闭。

### 6.2 总评（散文体）

一篇连贯文章，**不是分条**。用户明确要求"一大段文章"，与分条版并存。

| 项 | 规范 |
|---|---|
| 篇幅 | **8 段，约 980–1100 字**（2026-10-27 增顺手段，原 7 段） |
| 段落结构 | 总起 → 中宫 → 明堂 → 四象与聚散 → 五行与具体宫位 → 杂物 → **顺手度** → 收束给法 |
| 文案库 | `app/prose_pool.py`，**89 个分支 × 5 条同义变体 = 445 条**；同一分支内 5 条字数极差 ≤ 12 字 |
| 选句 | 按桌面指纹 `prose_pool.seed(result)` 取模（各段偏移不同）。**不用 random**——同一张盘反复打开必须同一版文字，只有桌面本身变了才换 |
| 排版 | 正文 12pt（宋体），行间 `spacing2≈9px`、段后 `spacing3≈14px`；各段首行缩进 2em；**不加编号、不加项目符号、不加小标题** |
| 版面（2026-10-25 重做） | 题头「总评」+ 右侧字数；细分隔线；**摘要条**：大号分数（Georgia 40，主色）+ `/100` + 评级（按分档取主题 grade 色）+ 一句话结论（`result.summary`）；正文首段**首字下沉**（2 倍字号、朱砂色）领起；收束段前一枚居中「· · ·」分隔，正文用次色收尾 |
| 生成 | 本地模板 + 按实情分支选句（分数档／中宫空否／白虎抬头否／杂物有无／最旺五行）；**不得联网、不得调外部模型** |
| 禁令 | 不出现"第一点/第二点"式罗列；不用表格；不堆砌术语 |

结尾固定落一句人话（"桌面不过是心绪的一张投影"），给收束，不给许诺。

### 6.2.1 总评与评分口径必须同源（2026-10-27）

评分从六项改成七项之后，总评的文案库**没跟上**，出现四处自相矛盾，
这一节留着当教训：

| 毛病 | 表现 | 现在怎么写 |
|---|---|---|
| 分项数写错 | "六项合参——中宫、明堂、四象、聚散、杂物、五行生克" | "七项合参……再加一项顺手"；断语阈值与 `fengshui.GRADES` 对齐（90/75/60/45） |
| 漏项 | 顺手 20 分，全文一字未提 | 单列第 7 段，讲步数与归类；**不许用气机、旺衰、吉凶** |
| 阈值不符 | 明堂 5–9 个就说"已经开始堵了"，而评分 8 个以内不扣 | 5–9 档说"刚过线、小扣"；10–14 档说"扣到五分封顶，不是硬伤" |
| 旧判词残留 | 四象说"口舌从侧边来""身不由己、替人奔忙"，同屏分条却说"不扣分" | 老话只作引用，紧跟一句"那是给院落用的，方寸之间不必套死"；并说明此项不扣分 |

另有一处**兜底词**要防：顺手度低时诊断 key 是「别手」，
`_NATURE` / `_ACTION` 里没有这个键就会退成「局面的顺逆」「动手改一改」，
句子读起来答非所问。两张表都已补「顺手 / 别手 / 尚可」三条，
`_smoke_stage13` 专门断言这两个兜底词不得出现。

## 9. 导出 HTML 规范

- 单文件，内联 CSS，**无任何外链**（字体走系统字体栈，不引 CDN）、无 JS。
- 版式：940px 居中、纸色背景、卡片面白、上下留白宽；语义标签用 `<header>/<main>/<section>/<footer>`。
- **标题带朱印**：`<span class="seal">風</span>`，34px 朱砂方框、反白宋体单字。
- 标题与数字用衬线栈（`Songti SC / SimSun / Georgia`），正文用仿宋栈
  （`SimSun / Songti SC / serif`）——与界面一致，全篇衬线。
  （界面 2026-10-27 统一为宋体，报告跟着改。）
- **总评首段做首字下沉**（`::first-letter`），3.3em、朱砂色——杂志编辑风，中文也成立。
- 诊断条目同样用「左竖线＋底发丝线」，不用四边框。
- 结构：header → 九宫盘 → 分数 → 总评 → 六项评分 → 三条重点 → 全部诊断 →
  **理想布局两档**（现状／最小调整并排 398px 各一，全部重排 760px 通栏）→ 附录 → footer。
- 附录必须写明："本报告由本地程序生成，未上传任何数据；结论基于形法模型，仅供自省参考。"
- 文件名：`风水报告_20261024_0020.html`

### 9.1 报告的交互（2026-10-24 新增，纯 CSS、仍无 JS）

| 交互 | 做法 |
|---|---|
| 悬停图标看名称 | 每个图标是一个 `<g class="ic">`，内含方块 + 两行 `<text class="tip">`（名称／五行·类型·宫位）。`:hover` 时 `opacity:0→1` |
| 悬停放大 | `.dot` 用 `transform:scale(1.5)`，配 `transform-box:fill-box;transform-origin:center` |
| 聚焦：其余变淡 | `.boardg:hover .cell:not(:hover) .dot{opacity:.45}` |
| 宫格高亮 | 图标放在所属宫的 `<g class="cell">` 里，所以"鼠标在图标上"等于"在本宫上"，`.cell:hover .cbg{filter:brightness(1.04)}` |
| 入场 | `@keyframes rise`：标题、盘、分数、诊断卡、总评段落淡入上浮 7px |
| 评分条生长 | `@keyframes grow`：`scaleX(0)→1`，六条错开 80ms |
| 卡片悬停 | 底色与边框过渡 + 上浮 1px |

- **提示文字的位置是算好的**：默认在方块上方，顶到画布上沿就翻到下方；靠左右边时改 `text-anchor` 为 start/end，保证不出画布。
- 提示文字用 `paint-order:stroke` + 同底色描边做"光晕"，压在宫格线与其它方块上也读得清，且不需要测量文字宽度。
- **打印时全部关掉**（`@media print`），跳提示也隐藏。
- **系统开了"减少动态效果"就全部关掉**（`prefers-reduced-motion`）。
- 仍然**没有 `<script>`、没有外链、没有图片**——纯 CSS 实现，离线红线不破。

## 10. 动效与交互（2026-10-24 新增，同日调平滑）

原则：**动效只服务于"看见了什么变了"，不服务于炫技**。不用弹跳、不用旋转、不用缩放整窗。

### 10.1 曲线

| 曲线 | 用在哪 | 理由 |
|---|---|---|
| `ease-out-cubic` `1-(1-t)³` | 数值滚动、图标放大、涟漪扩散 | 起手快、收尾缓，最接近"松手之后自己停下" |
| `ease-in-out-cubic` | 指示条滑动、宫格点亮 | 位移要两头都缓，否则起步像被踹了一脚 |
| `smoothstep` `t²(3-2t)` | 文字淡入、宫格底色 | 纯透明度变化，用最柔的曲线 |
| `ease-out-back(1.1)` | 图标浮起 | **过冲只要 1.1**，原值 1.7 会"跳"一下 |

**全局进度一律线性推进**，缓动交给各元素自己的曲线。全局再叠一层缓动，会让前半段发闷、后半段抢。

### 10.2 时长

| 时机 | 效果 | 时长 |
|---|---|---|
| 启动 / 换主题 / 换字号 | 宫格由中宫向外点亮 → 图标逐个浮起 → 文字与图例淡入 | **900ms** |
| 换朝向 | 同上（盘面结构变了，稍快一点） | 620ms |
| 分数变化 | 数字滚到新值，颜色由朱褐回落墨色，落定后轻微放大一记 | **650 + 220ms** |
| 评分条 | 六条错峰生长 | **780ms** |
| 三档切换 | 选中项加粗变主色，底部指示条滑过去 | 240ms |
| 分条／总评页签 | 指示条滑动 | 220ms |
| 诊断卡列表 | 每条比前一条晚 28ms 出现 | 28ms × n |
| 图标悬停 | 圆角方块放大到 1.55 倍并描边 | 170ms |
| 图标移出 | 缩回原尺寸 | 140ms |
| 提示框 | 淡入并上移 6px | 190ms |
| 宫格悬停 | 该宫描边淡入 | 150ms |
| 点击图标 | 涟漪扩散并淡出 | 460ms |

### 10.3 实现要点

- **帧率 60fps**：`_frames(dur)` 按 16ms 折帧。原来 26ms 一帧（38fps）能看出顿挫。
- **淡入的做法**：Canvas 没有 alpha，一律把颜色向底色混合（`_mix`），文字像从纸里浮出来。
- **悬停不重绘整盘**：只改那一个图元的顶点（圆角多边形的点数固定，可原地换点）。
- **揭示动画期间禁用悬停**：`revealing` 状态位挡住鼠标事件，否则悬停的图元会被下一帧删掉。
- **启动补一帧动画**：构造时窗口还没映射，`winfo_viewable()` 为假；`after(120ms)` 后再播入场，否则用户看不到。
- **窗口不可见时不动画**，冒烟测试因此仍能拿到最终数值。
- **令牌机制**：每个动画 `_bump(name)` 拿号，回调先比号，过期帧直接 return。
- 右上角「动效 · 开／关」可一键关闭；关闭后所有数值**立即**到位（尊重减少动效偏好）。

### 10.4 禁止用「改字号」模拟缩放（2026-10-27）

分数落定时原本有个「从 90% 放大到 100%」的脉冲。Tk 没有 transform，只能靠改字号，
而改字号是**离散跳变**：40 → 36 一步到位，再用 220ms 长回 40。
视觉上就是数字猛缩一下又鼓起来，用户读成"卡了一下"。

- **凡是要变尺寸的动效，先确认容器会不会跟着变**。分数盒子已用
  `pack_propagate(False)` 锁死宽高，所以尺寸不会传导；但**字形本身在变**，
  在视觉上就等于抽动——锁住容器并不够。
- 结论：**尺寸类动效在本项目一律不做**。要"落定感"就用颜色（`_fade_in` 从
  accent 渐到 ink）或间隔，不用字号。`_smoke_stage6` 已加断言：
  滚动期间字号集合与盒子尺寸集合都必须只有一个值。

### 10.5 其它交互

- 左右分栏可拖动（光标变双向箭头），**双击复位到 62%**。
- 鼠标移到图标上，光标变手型。
- 小按键（A−／A＋／动效）按下时底色压深 120ms 再回弹。

### 11.2.1 表单标签列：按像素定宽，别用 width=字符数（2026-10-25）

tkinter 的 `width=N` 是**字符平均宽**（以 `0` 为基准），一个汉字远宽于这个平均值。
用 `width=5` 装「盘上标记」四个字，标签会被裁成「盘上标」，紧贴着的右侧控件
看起来就像"把字挡住了"——用户就是这么报的（截图确认）。

规则：设置面板等表单的标签列统一用
`Frame(width=实测像素宽, height=字体行高) + pack_propagate(False) + Label(anchor="w")`，
宽度取 `tkfont.Font(...).measure(最长的那个标签) + 8`，随字号档自动变。
已封装为 `_build_settings_panel` 内的 `row_label()`。

### 11.2.2 文本选中态必须显式设前景（2026-10-25）

tk.Text 的 `selectforeground` 默认是**白色**。本设计选中底色是暖白 `#EFE9DC`，
于是"选中/复制"时文字变白、看着像内容消失（用户原话：复制变白，太丑了）。

规则：凡是设了 `selectbackground` 的 Text，**必须同时设
`selectforeground=th["ink"]`**；预览类只读文本、总评、导出预览都适用。

### 11.3 设置（Windows 原生弹窗，2026-10-24 定稿）

> 演进：Frame 浮层 → 居中覆盖层+模拟阴影 → **Toplevel 原生弹窗**（用户两轮反馈后定稿）。
> 教训已记入 devlog：能用 OS 原生的就不自制。

- 触发：右上角齿轮（Canvas 矢量绘制：外圈+内圈+八齿，弱文字色，悬停转主色）。
- 形态：`tk.Toplevel`，`transient(root)`（不进任务栏）、不可缩放，系统边框，
  **无自制阴影／描边**。宽度取内容需求宽（≥420），水平居中、垂直 1/3 处。
- 应用模态：`grab_set`。**必须 `wait_visibility()` 之后才能 grab**——deiconify 是异步的，
  对未映射窗口 grab 会失败或产生悬空模态（主窗假死，2026-10-24 实测踩坑）。
- 抬升：`deiconify` 后必须显式 `lift()`，Toplevel 不会自动盖过主窗。
- 分区顺序：外观（主题／**字体**／字号／动效／盘上标记）→ **导出报告**（报告字体／报告字号）→ 五行对应表 → 底部「关闭」
- **界面字体与报告字体分开设**（2026-10-27）：界面字体走 `font_family` + 重建；报告字体走 `report_font` / `report_size`，只影响导出的 HTML，改完不重建，状态栏提示「下次导出生效」。报告字号用整页 CSS `font-size` 等比缩放，版面留白（padding 的 clamp）不跟着变。。
- 关闭：标题栏 X、Esc、「关闭」按钮。`close_settings` 无条件 `grab_release`，
  防任何路径留下悬空 grab。
- 打开序列包 try/except，失败即回滚状态并收窗——绝不允许"状态开着、窗口不见"。
- 弹窗开着改主题／字号：走 `_rebuild()`（销毁重建 Toplevel 后原样重开）。

  左侧加「导出选项」引导词。原来用 `_chip` 画，和「导出」并排就是第三个按钮。
- 预览区：`Text` 只读、可选中复制（防止用户想手动改）。
- 禁用态：未填生辰时四套 chip 变灰并加「需先填生辰」小字；未分析时整栏灰。
- **预览框必须给 `height=7` 之类的最小行数**：tk.Text 默认 24 行，会把下面的「换一版/选项/补充背景/上次导出/底部提示」整块挤出可视区（2026-10-25 截图确认）。
- 底部提示行 `wraplength` 随栏宽变化（绑 `<Configure>`），否则窄栏会把末尾两字挤到下一行。

### 11.6 底部一行提示（固定写在问 AI 栏底部）

> 文件里已带评分规则，AI 不需要猜。如果它的结论里没有出现文件中的数字，多半是没读——
> 换「审稿」再试一次。

### 11.7 分图标页（2026-10-27 新增）

二级页签顺序：`分条 ｜ 分图标 ｜ 总评`，分图标夹在中间。

**两级折叠**（默认全合）：

```
▸ 巽宫 · 东南 · 12 个 · 平均 41　忌        ← 宫位行：三角 + 摘要 + 等级
  Snowand-     金 · 克入          相冲     ← 图标行：名称 + 五行·关系 + 判定
    现  它是金，金克巽宫的木，这一格被它顶着。   ← 点开：三段
    理  巽宫属木，主沟通、文书、消息通达，是「进出」的一格。
    改  优先挪走。坎宫（下中·水）受得住它，留在这里只会一直顶着巽宫。
```

- **图标行懒建**：宫位行点开时才建该宫的图标行。46 个图标全建是 46×4 个 Label，
  切页签会明显卡。
- **折行宽度要在 pack 生效后再取**：`winfo_width()` 未布局时返回 1，
  保底值会把 20 字的句子硬折成两行（2026-10-27 截图发现）。
- 等级配色：吉=high、平=mid、忌=low；图标判定按 70/45 分档同色。
- 展开状态存在 `_picon_open` / `_picon_icon_open`，切页签回来保持。
- 图标名超过 26 字截断加「…」，免得一行被名字占满。
- **展开/折叠有动效**（2026-10-27 加）：展开一宫时图标行 14ms 一条往下长，
  点开一件时「现／理／改」12ms 一段弹出；折叠时倒序 10ms 一条收回去。
  动效关掉（设置里）就一次性到位。用动画令牌 `_bump("picon")`，
  连点两下时旧动画自动作废，不会两边抢着 pack。
- **底部固定图例**：五种判定各一句话，颜色取主题的 `tone5`（不是写死的色值），
  换主题时图例跟着变。图例用 `side="bottom"` 先 pack，滚动区吃剩下的空间。
- HTML 报告用同一份结构，`<details>/<summary>` 折叠，仍然零 JS；
  展开动画用 `@keyframes` + `nth-child` 逐条延迟，并尊重 `prefers-reduced-motion`。

### 11.7.1 盘面文字压在图标上时的可读性（2026-10-27 新增）

宫名（坎 北、巽 东南）与图标色块**允许重叠**——图标按真实坐标画，
宫名固定在宫格左下角，两者天然会撞。要的不是错开，是**重叠也读得清**：

| 端 | 问题 | 修法 |
|---|---|---|
| 程序（Tk canvas） | 宫名最后画、永远在最上层，主色直接填充，压在五彩色块上笔画被"吃"掉 | `render._halo_text()`：同位置先画上下左右四道 `th["card"]` 色的偏移文字，再画正文——合成出底色描边，把字从色块里"抠"出来。宫名、计数、「中宫空 · 吉」全部走它；描边粗细 `max(1, 1.1×fs)`，随文字一起淡入 |
| HTML（SVG） | SVG `<text>` 默认拦截鼠标事件：宫名压住图标时，hover 命中的是文字，`.ic:hover` 永远不触发，tooltip 出不来 | CSS 一行 `.board-svg text{pointer-events:none}`——所有盘面文字对鼠标透明。tip 本身只在 `.ic:hover` 时显示，穿透不影响它 |

考虑过并放弃的方案：文字下垫卡片色矩形（可靠但有"补丁"感）；
图标多时把宫名挪去空角落（复杂且挤满时无处可挪）。

### 11.8 顺手度这一项的语气（2026-10-27 新增）

「顺手度」**不是风水项**，文案里不许出现气机、旺衰、吉凶这类词。它只说两件事：
鼠标要走多远、东西按类别归没归堆。

- 对：`常用的多在三边顺手位（顶、左、右）`、`5 件归档物还占着顺手位`
- 错：`此位得气，主事顺`、`白虎稍盛，恐有口舌`
- 判「述」的四象、「顺手度」的「理」都要明确写一句「只作说明／不是对错」，
  避免用户以为这是新型恐吓。

### 11.8 历史页三模块分色（2026-10-27）

历史页原来整页一张 `card` 底，趋势图、日历、全部分析记录连成一片。
现在三模块用**同主题的三档近似色**自然分层：

| 模块 | 底色 | 宣纸主题实际值 |
|---|---|---|
| 趋势图 | `th["sunk"]`（下沉感，图在凹槽里） | #F1ECE1 |
| 快照按钮 + 日历 + 当日列表 | `th["card"]`（主卡，不变） | #FEFDFB |
| 全部分析记录 | `th["bg"]`（最暗，像档案区） | #FAF8F3 |

**不新增色键**——card / sunk / bg 本来就是每套主题里同色系的三档明度
（墨夜 card #1C2022 / sunk #23282A / bg #15181A），换主题自动联动。
`_fill_history()` 的行与容器同步用 `bg`，别只改容器不改行（会出现色差断层）。

### 11.8.1 总评页的两个坑（2026-10-27）

1. **限宽必须左右对称**。原实现只给左边补 `(w-48-MAX)//2`、右边固定 24，
   窗口一最大化就把内容块推到右边贴着右沿。正确写法是两边各补一半。
2. **中文用 `wrap="char"` 而不是 `"word"`**。Tk 的 word wrap 会把「·」「，」
   当断行点，结果行尾参差、逗号跑到行首。中文本来逐字可断，char 更整齐
   （代价：长英文单词可能在字母间断开，本项目总评里英文很少，可接受）。

### 11.9 文案语气（新增部分）

- 命主相关内容**不做吉凶恐吓**：说"这一方对你偏助"而不是"大吉"；说"这一方与你相冲"而不是"大凶"。
- 不做命理承诺：不出现"必发财""必升职"这类话。
- 命主栏底部固定一行小字：`命卦与纳音仅作参考，不构成对个人运势的判断。`
