## 阶段 1 · 读

**目标**：把桌面读成 `Layout` 结构，落成 JSON，命令行可查。不碰界面。

**产出**

- `app/desk_reader.py`：`read_layout() -> (Layout, warnings)`
- `app/__init__.py`（空）
- 命令行入口：`python app\desk_reader.py` 打印摘要 + 写出 `data/layout_debug.json`

**实现要点**

- Progman → DefView → SysListView32，带 WorkerW 回退
- `SendMessageTimeoutW` 1s 超时
- 进程级 DPI 声明（per-monitor v2）
- 网格尺寸由坐标差推导（`LVM_GETITEMSPACING` 实测为 0，不用）
- 名称 → 扩展名：枚举 Desktop + Public Desktop 做匹配
- 只读：不调用任何 SET 类消息

**验收清单**

- [ ] 图标数与实际桌面一致（含系统图标：此电脑/回收站/网络/控制面板）
- [ ] 扩展名匹配成功率 ≥ 90%，未匹配项在 JSON 里标 `low_confidence`
- [ ] 单元格尺寸推得出来，且与目视间距吻合（相邻图标坐标差一致）
- [ ] 桌面「自动排列图标」开/关两种状态下都能正常读取
- [ ] 运行期间无任何窗口弹出、桌面图标无位移
- [ ] 找不到桌面时给出明确中文错误，不崩溃

**风险点**：R1（非标准壳）、R5（权限）

## 阶段 2 · 看

**目标**：窗口能开，盘画得对，朝向能切。此时还没有任何风水结论。

**验收清单**

## 阶段 3 · 断

**目标**：出结论。这一阶段最重，也是唯一需要你判断"说得通不通"的阶段。

**产出**

- `app/classify.py`：白名单 → 语义词典 → 扩展名 → 颜色系数
- `app/fengshui.py`：九宫归属、生克统计、形法条目、六项评分、五档断语
- `app/main.py`：右栏诊断卡渲染
- 每条诊断带 `wuxing_source`，界面可查判定来源

**实现要点**

- 五行表与语义词典严格照 `01-需求规范.md` 第 4 节
- 形法条目：中宫、明堂、四象左右、聚散、杂物煞、空宫、穿心
- 评分六项从满分起扣，权重 15/15/15/15/20/20
- 每条形法都产出 `evidence` 字段（带具体数字或图标名）
- 图标主色提取（`SHGetFileInfoW` + `GetDIBits`），仅算强度系数，失败静默 1.0

**验收清单**

- [ ] 全部图标都有五行归属，无"未分类"
- [ ] 抽查任一图标，能说清它为什么是这个五行（来源字段可查）
- [ ] 每条诊断四要素齐全（现象/依据/原理/建议），无缺项
- [ ] 建议里点名了具体图标与目标宫位，不是"建议清理"
- [ ] 总分与五档断语对应正确
- [ ] 断网运行，功能与联网完全一致
- [ ] 文案里没有任何"大凶/血光/必破财"类表述

**风险点**：模型是否自洽 —— 这条只能你来判

## 第三轮 · 收尾修正（2026-10-27 13:00）

用户报三处，逐条改：

### 追加：分数落定脉冲（2026-10-27 13:20）

用户报「改完还抽」。逐帧采样（240 帧 × 8ms）证明**盒子与卡片高度全程不变**
（98×101、卡高 354），只有字号在变：

```
帧023  Georgia 40   text=81   ← 650ms 滚动结束
帧037  Georgia 37   text=81   ← 一步缩到 37（pulse 第 0 帧 = 0.90×40）
帧041  Georgia 38
帧043  Georgia 39
帧049  Georgia 40   ← 220ms 长回来
```

即 `_pulse_score()` 的「落定后放大」动效。Tk 只能靠改字号模拟缩放，
改字号是跳变，所以看起来是先猛缩再鼓起来。**该动效已删除**，
落定感改由滚动本身的淡色→浓色承担。

- `_smoke_stage6` 新增：滚动期间字号集合、盒子尺寸集合都必须只有一个值；
  `_pulse_score` 不得再出现。
- 复测：首次分析 240 帧内只有首帧一次状态切换；重复分析 12 次变化全是数字在滚，
  几何与字号一动不动。
