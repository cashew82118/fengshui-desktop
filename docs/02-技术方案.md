## 2. 图标读取方案（已实证）

### 2.1 定位链路

```
FindWindow("Progman")
  └─ FindWindowEx(.., "SHELLDLL_DefView")
       └─ FindWindowEx(.., "SysListView32")   ← 桌面图标都在这
```
若 Progman 下找不到，则回退：`EnumWindows` 遍历所有 `WorkerW`，取第一个含 `SHELLDLL_DefView` 子窗口的。
（Win11 24H2 起部分版本把 DefView 挪到 WorkerW 下，两条路都要有。）

### 2.2 读取方式

跨进程读内存，不改任何东西：

| 操作 | 消息/API | 说明 |
|---|---|---|
| 图标数量 | `LVM_GETITEMCOUNT (0x1004)` | — |
| 图标位置 | `LVM_GETITEMPOSITION (0x1010)` | lParam 指向**目标进程**内的 POINT |
| 图标名称 | `LVM_GETITEMTEXTW (0x1073)` | 需在目标进程内构造 `LVITEMW`，pszText 指向远端缓冲 |
| 网格间距 | `LVM_GETITEMSPACING (0x1033)` | **实测返回 (0,0)，不可靠**，见 2.4 |

进程句柄：`OpenProcess(PROCESS_VM_OPERATION|VM_READ|VM_WRITE|QUERY_INFORMATION)`，远程缓冲用 `VirtualAllocEx`。

### 2.3 已实测事实（2026-10-24 探针）

| 项 | 说明（具体数值以各机器实测为准） |
|---|---|
| 图标数 | 桌面文件夹 + 公共桌面 + 系统图标合并去重 |
| 列表控件客户区 | 整屏尺寸（非工作区） |
| `sizeof(LVITEMW)` x64 | 88 字节（结构体定长，与分辨率无关） |
| 单元格尺寸 | 由相邻图标坐标差推出，每台机器不同 |
| 坐标含义 | 单元格**左上角**，y 从 2 起算 |
| 是否自动排列 | 否（存在跨列空隙，位置为用户手动排布） |
| Explorer PID | 运行时动态获取，不固定 |

### 2.4 网格间距的求法（重要）

`LVM_GETITEMSPACING` 实测返回 0，**不能依赖**。改用坐标差推导：
取所有 x 的去重值排序，最小正差即 `cell_w`；y 同理。若只有一个 x（全在一列）则用 `cell_w = 桌面图标尺寸 + 边距` 估算并把 `cell_w` 标记为"推定值"，仅影响绘制不影响分析。

### 2.5 名称 → 真实扩展名

Windows 默认隐藏扩展名，`LVM_GETITEMTEXT` 返回的是**显示名**（`新建 文本文档` 没有 `.txt`，`DLSS 5 Swapper` 没有 `.lnk`）。五行归类必须拿到真实扩展名，做法：

1. 枚举 `%USERPROFILE%\Desktop` 与 `C:\Users\Public\Desktop`，建立两张映射：`完整文件名 → 扩展名`、`词干 → 扩展名`。
2. 匹配顺序：完整名命中 → 词干命中 → 名内自带已知扩展名 → 全部落空则视为**虚拟项**（系统图标/网络位置），交 4.1 白名单或语义词典处理。
3. 重名冲突：同词干多个文件时优先取 `.lnk`；仍冲突则取字母序第一并标记 `low_confidence=True`。
4. **文件夹陷阱**：`Path("OK自动任务v1.1").suffix` 得到 `.1`，会把文件夹误判成文件。必须先用 `entry.is_dir()` 判定，**文件夹的扩展名强制置空**，`kind` 标为 `dir`。阶段一实测已踩到并修正。
5. 三者之外还有一个类别：**系统虚拟项**（此电脑/回收站/网络/控制面板/网络位置），没有任何对应文件，`kind` 标为 `virtual`，`path` 为 `None`，交给阶段三按白名单处理。

### 2.6 DPI 处理

进程启动第一件事（**必须在 `Tk()` 创建之前**）：
```python
SetProcessDpiAwarenessContext(-4)   # PER_MONITOR_AWARE_V2
```
失败则退 `SetProcessDPIAware()`。否则 125%/150% 缩放下坐标会被系统虚拟化，盘会画歪。

### 2.7 阻塞防护

`SendMessageW` 在 Explorer 忙时可能长时间阻塞。改用 `SendMessageTimeoutW(.., SMTO_ABORTIFHUNG, 1000ms)`，超时即判定"读取失败"并走降级提示，绝不卡死界面。

### 2.8 软件名录匹配（三级，防假阳性）

`app/software.py` 收录约 480 条具体软件名，按五行五类组织（木 130 / 火 123 / 土 40 / 金 92 / 水 99）。

| 规则 | 说明 |
|---|---|
| **最长关键词优先** | 索引按关键词长度降序排好。否则「小黑盒加速器」会被短词「小黑盒」抢走，「Visual Studio Code」会被「visual studio」抢走 |
| **全 ASCII 关键词 → 词边界** | 前后不得紧邻 ASCII 字母数字。否则 `edge` 会命中 `knowledge`、`ea` 会命中 `idea`、`ps` 会命中 `photoshop` 内部 |
| **驼峰也算词边界** | `CodeBuddy` 能命中 `code`（小写紧跟大写视为断词） |
| **含中文关键词 → 子串** | 但**两侧必须先统一小写**：`QQ音乐` 必须命中 `qq音乐`，否则会被短词 `qq` 抢走（2026-10-24 实测踩到） |

禁用两类词：**泛词**（`备份`／`还原`／`邮件`／`书架`／`装机`，必然到处误伤）与**二字母缩写**（`ai`／`ps`／`pr`／`ae`，改用全名 `illustrator`／`photoshop`／`premiere`／`after effects`）。

## 3. 坐标模型

### 2.9 布局推演（只算不改）

`app/project.py` 产出"如果这样摆会怎样"的虚拟布局，**绝不移动真实图标**。

#### 两条不能犯的错

1. **不能按像素三等分定位。** 整屏宽 ÷ 3 几乎不可能恰好是单元格宽的整数倍，按像素分会把图标推到格子外，
   对齐度从 100% 掉到 70% 以下（实测踩过，推演后形态分反而降了 3.6）。
   必须**按网格索引切宫**：总列数 `(W-cw)//cw+1` 三等分，总行数 `(H-ch)//ch+1` 三等分（例如 11 行＝4/4/3）。
2. **不能做九宫均摊。** 把图标摊到所有宫，气是"周"了，但人懒得去点右边和右下。
   周流指标本身也改了：**占满 6 宫即满分**（原按 9 宫算，等于奖励摊满），
   否则推演会被指标逼着往角落里撒。

#### 推演原则

| 原则 | 落地 |
|---|---|
| 只动必须动的 | 只处理「中宫有物」与「明堂超 4 个」，其余一概不碰 |
| **贴屏幕边填，不贴宫界** | 每宫从**朝向屏幕边的那一侧**开始填：左列从左往右、右列从右往左、上行从上往下、下行从下往上。见 2.10 |
| 就近安置 | 距离项 `-0.9 × 曼哈顿距离`，移动距离不得超 2 宫 |
| 顺手优先 | `-0.30 × (行+列)`，越靠左上越好；土类（文件夹/安装包/素材）权重降到 0.35，可放远处 |
| 成组不打散 | 目标宫已有同五行者，`+0.35 × min(3, 同五行数)` |
| 别太挤 | 单宫超 8 个不再往里塞 |
| 只补空位 | 目标宫只找空着的格位填入，**不重排原有图标** |

### 2.10 填格方向：贴屏幕边，而不是贴宫界

若每个宫都从**自身左上角**开始填，图标贴的是"宫界"而不是"屏幕边"：
坤宫（右上）的图标会从屏幕三分之一处才开始排，右边反而空着；兑宫（右中）
的图标会堆在中间偏右，最右边空着。这不是人摆桌面的样子，中间也没能空出来。

正确做法：**每个宫从朝向屏幕边的那一侧开始填。**

```
hs = 左列/中列从左往右，右列从右往左
vs = 上行/中行从上往下，下行从下往上
格位顺序 = [ (h, v) for h in hs for v in vs ]
```

效果：巽宫占屏幕左上角、坤宫占右上角、艮宫占左下角、乾宫占右下角，
兑贴右边、坎贴下边，**中间自然空出一大片**。

### 2.11 形态第三项：中庭留白（不是"贴边"）

原来形态分项第三项算的是「贴边率」，把贴边当**缺点**扣分（"贴边则无退路"）。
这与"四周贴边、中间留白"的实际习惯正相反，2026-10-24 按用户反馈改掉。

现在算的是**中庭留白**：盘心 40% 见方区域（`cx, cy ∈ [0.30, 0.70]`）内的图标占比，
**越低越好**，超过 25% 扣满。形法叫「外实内虚」——四周有落处，中间有回旋。

形态三项权重：对齐 45% ／ 周流 30% ／ 中庭 25%。
贴边率仍统计在 `stats.edge_n`，只作说明、不参与评分。

实测验证：移 6 个（兑宫 5 个贴右边缘、坎宫 1 个贴下边缘），69 → 81 分；
形态 14.2 → **15.0（满分）**；中庭图标 0 个；占 7 宫；未移动的图标原样保留。

## 3. 坐标模型

- 分析用**归一化坐标** `(x/W, y/H)`，`W,H` 为列表控件客户区尺寸。这样换分辨率不影响结论。
- 九宫边界：`col = min(2, int(nx*3))`，`row = min(2, int(ny*3))`。取图标**单元格中心**判断归属，不用左上角（避免边界抖动）。
- 从单元格中心反推四象位置：`left = nx < 1/3`、`right = nx >= 2/3`。

### 5.1 主题与字号（2026-10-24）

- 主题表 `THEMES` 覆盖**所有**颜色键：底/卡片/墨/次/弱/线/主色/印章/盘底/宫色/中宫/滚动条/五行/吉凶/分数档。界面与绘制层只读表，不写死色值。
- 换主题或换字号走**重建界面**（`_rebuild`）：销毁 `_frames` → `_build()` → 恢复数据 → 播放揭示动画。约几十毫秒，比逐个 widget 重设颜色可靠。
- 重建前必须 `unbind_all("<MouseWheel>")`，否则滚轮绑定会累积（每次重建多绑一层）。
- 重建后要 `_sync_seg()` 还原当前档位高亮，否则三档全变灰。
- 字号倍率作用在整张字体表上；`render.fit_board` 从字体表反推倍率（用最大号字反推，取整误差最小），据此算盘面上下留白。
- 偏好写 `data/prefs.json`，读失败静默回默认值——偏好坏了不该让程序开不起来。

### 5.2 动效实现要点

| 问题 | 做法 |
|---|---|
| Canvas 无 alpha，怎么淡入 | 把前景色向底色混合。`text_t` 从 0→1，颜色从"等于底色"渐变到本体 |
| 动画被打断怎么办 | 每个动画一个**令牌**（`_bump(name)`），回调先比令牌，过期帧直接 return |
| 无窗口测试怎么跑 | `_can_anim()` 要求 `anim_on and winfo_viewable()`；withdraw 状态下直接落位 |
| 揭示动画期间悬停失效 | 每帧 `_draw` 会重建图元，`revealing` 为真时 `_on_motion` 直接返回 |
| 防定时器泄漏 | 布局未就绪时的重试带 `_tries` 上限（20 次），不无限 `after` |


## 6. 绘制规范（摘要，详见 03）

- Canvas 尺寸按盘的真实宽高比缩放，**随窗口大小自适应、不设上限**（原 560/820 上限已取消，上限会让大窗口里的盘原地不动）。上下留白随字号联动。
- 图标画为小方块，边长 = `cell_w * scale * 0.5`，最小 3px（0.19 实测只有 4px，看不出布局）；悬停时放大到 1.55 倍并加一圈主色细边。
- 九宫格线 1px（Canvas 最小 1px），外框 1px 深一档。
- 各宫底色取主题的 `cell_tint`，混合比例按该宫图标数分级：0 → 0、1–4 → 0.10、5–9 → 0.18、10+ → 0.26。

## 7. 风险清单

| 编号 | 风险 | 应对 |
|---|---|---|
| R1 | 桌面非标准 Explorer（第三方壳） | 找不到列表控件时明确报错"未检测到标准 Windows 桌面"，不做假的兜底 |
| R2 | 图标名匹配不到文件（虚拟项） | 走白名单/语义词典；仍失败归金并标 `low_confidence`，诊断里不引用其类型 |
| R3 | 多显示器：控件跨虚拟桌面，坐标可能为负或偏移 | v1 只按控件矩形整体划分九宫；检测到 `monitors > 1` 在界面顶部显式提示"多屏下结论仅供参考" |
| R4 | Explorer 繁忙导致 SendMessage 阻塞 | 全部改用 `SendMessageTimeoutW`，1000ms 超时 |
| R5 | 权限不匹配导致 OpenProcess 失败 | 提示"请勿以管理员身份运行本程序"（explorer 通常是普通权限） |
| R6 | DPI 虚拟化导致坐标缩放 | 进程级 per-monitor v2 声明；并在 `read_layout` 里**检测越界**：任一 `cx/cy > 1.002` 即判定坐标与画布不匹配，写入 warnings 明确报警，绝不静默算错宫位。**实测已踩到**：机器开启 125% 缩放时，未声明 per-monitor v2 则 `GetClientRect` 返回虚拟化尺寸（物理像素 ÷ 缩放系数）而坐标仍是物理像素，宫位随之整体错位（如 巽12离10坤8 错成 巽9离7坤9） |
| R7 | 图标数为 0 | 友好提示，不进入分析流程 |
| R8 | 图标主色提取失败 | 静默取强度 1.0，不报错、不阻断 |

### 9.2 启动闸门对现有代码的影响（本轮最大改动）

现状：`App.__init__` → `scan()`（读桌面 → 分析 → 写历史 → 绘制）。
改为：

```
App.__init__ → _build() → 绘制空盘（reveal=1，无数据）
用户点「开始分析」→ App.analyze() = 原 scan() 的逻辑
```

- 新状态位 `self.ready: bool`，初值 False。
- 所有依赖 `self.result` 的路径（右栏、导出、推演、问 AI）都要判 `ready`。
- **历史只在用户点击后写**，构造时绝不写。
- **现有 5 套冒烟测试全部依赖"构造即分析"**，必须逐个改为：构造 → `app.analyze()` → 断言。
  这是本轮的隐性工作量，必须在阶段 6 一次改完，不留半坏状态。

### 9.4 命卦算法（实现时必须核对）

先按公式实现，**再用公开命卦表抽样核对，不符就改查表法**：

```
年干： (year - 4) % 10  → 0甲 1乙 2丙 3丁 4戊 5己 6庚 7辛 8壬 9癸
年支： (year - 4) % 12  → 0子 1丑 … 11亥
男命： (100 - 年尾两位) % 9，余 0 作 9
女命： (年尾两位 - 4) % 9，余 0 作 9
卦数： 1坎 2坤 3震 4巽 5(男坤/女艮) 6乾 7兑 8艮 9离
```

- **按立春分年**：1 月 1 日–立春之间出生算上一年。立春日期按年计算（约 2 月 3–5 日），
  实现时内置 1950–2050 的立春表（每年一个日期），不做天文计算。
- 2000 年及以后的公式需要另取（上述两式对 2000 年后会出负数），实现时一并核对。
- **验收必须包含**：抽 1970／1985／1990／2000／2010 五个年份 × 男女共 10 组，
  与公开命卦表逐一对齐，全对才算过。

### 9.6 设置浮层

- **不用 Toplevel**（避免多窗口管理），用一个 `tk.Frame` 以 `place` 覆盖在右栏之上，
  背景同 `card`，加 1px 边框，z-order 自然在最上。
- 点外部关闭：根窗口绑 `<Button-1>`，判断点击坐标是否落在浮层 bbox 内。
- `Esc` 关闭：`bind_all("<Escape>")`，关闭时解绑。
- 「变更立即生效」：主题／字号改动沿用现有 `_rebuild()`；五行表改动后
  `rules` 自带缓存刷新（set/remove 内部已同步），界面层只需重新
  `_analyze()` + `_draw(1.0)`——classify 无缓存，重算即生效（9.1 的
  invalidate_cache 设想未落地：实测无缓存可失效，删繁就简）。
